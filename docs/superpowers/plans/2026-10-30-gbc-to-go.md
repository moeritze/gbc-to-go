# gbc-to-go Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A forkable single-owner GB/GBC web emulator on Firebase Spark (Hosting + Auth + Firestore), with in-browser ROM upload, cloud saves and save states, plus human and agent setup docs, and a live proof-of-concept instance.

**Architecture:** Static ES modules in `web/` served by Firebase Hosting; binjgb WASM runs the game. ROM bytes live in Firestore as ≤900 KiB chunk docs and are cached per device in IndexedDB. Firestore rules lock everything to one owner UID substituted at deploy.

**Tech Stack:** Plain HTML/CSS/JS (no bundler), Firebase JS SDK 13.1.0 from the gstatic CDN, binjgb (vendored), Node `node --test` for unit tests, `firebase-tools` via `npx`.

**Spec:** `docs/superpowers/specs/2026-10-30-gbc-to-go-design.md`

## Global Constraints

- Firebase Spark only: no Cloud Storage, no Cloud Functions, no Blaze-only feature. Firestore `(default)` database.
- No Firebase emulators anywhere. Live checks use the real project.
- Firebase SDK pinned to `13.1.0` (CDN URLs in `web/firebase.js` and `firebase` devDependency must match).
- Chunk size `CHUNK = 900 * 1024` bytes. Rules caps: chunk ≤ 921600 B, sram ≤ 131072 B (+ RTC bytes if the core appends them, see Task 4), state < 1000000 B.
- `romId` = lowercase SHA-1 hex of the ROM bytes.
- Never commit: `*.gb`, `*.gbc`, `*.sav`, `.firebaserc`, `deploy.env`, `web/firebase-config.js`, `.build/`, `.superpowers/`, `.remember/`.
- No `window.alert/confirm/prompt`; use in-app dialogs (`<dialog>`).
- Copy in English. MIT license.
- Source reference (read, copy, adapt; no dependency): `~/repositories/poke-recomp/` — `web/player.js`, `web/touch.js`, `web/vendor/*`, its deploy script, `scripts/verify-rules.mjs`.
- `.claude/autonomy.json` = `{ "stage": "dev" }`: verify = unit tests + live smoke; no e2e suite.

## Review Focus

1. A file that is not a GB ROM (zip, image, truncated dump) is uploaded → rejected with a clear message, nothing written. Test in Task 1 (`parseHeader` throws).
2. ROM sizes exactly at chunk boundaries (921600, 1843200) and the 8 MiB max → split/join round-trips byte-identical. Test in Task 1.
3. Upload interrupted halfway → library never shows a half ROM (chunks + meta in one `writeBatch`; meta lives in the same batch). Pinned in Task 3 by `uploadPlan` test: last op is the meta doc.
4. Phone and laptop both played offline; older save must not overwrite newer → `pickNewer` compares `updatedAt`. Test in Task 3.
5. A different account signs in (someone created one) → app shows "This account is not the owner of this site." instead of an empty library or crash; rules deny. Live check in Task 7 (`verify-rules.mjs`), UI branch in Task 5.

### Task 2: Firebase wiring, rules, deploy script

**Files:**
- Create: `web/firebase-config.example.js`, `web/firebase.js`, `rules/firestore.rules`, `deploy.env.example`, `scripts/deploy.mjs`

**Interfaces:**
- `web/firebase-config.example.js` exports `firebaseConfig` (placeholders) and `appCheckSiteKey = ''`.
- `web/firebase.js` exports `app, auth, db` and re-exports from the CDN: `onAuthStateChanged, signInWithEmailAndPassword, signOut, doc, collection, getDoc, getDocFromServer, getDocs, setDoc, deleteDoc, writeBatch, serverTimestamp, Bytes, query, orderBy`. Auth persistence `browserLocalPersistence`. If `appCheckSiteKey` non-empty: `initializeAppCheck(app, { provider: new ReCaptchaV3Provider(key), isTokenAutoRefreshEnabled: true })` before `getFirestore`.
- `rules/firestore.rules`: template with `__OWNER_UID__`; `function owner() { return request.auth != null && request.auth.uid == '__OWNER_UID__'; }`. Paths: `roms/{id}` read/write owner; `roms/{id}/chunks/{n}` read/delete owner, create/update owner and `request.resource.data.data is bytes && request.resource.data.data.size() <= 921600`; `saves/{id}` owner + `sram is bytes && sram.size() <= 131072 + 64` (adjust in Task 4 if RTC bytes differ); `states/{id}` owner + `state is bytes && state.size() < 1000000`; `settings/main` owner; everything else denied.
- `deploy.env.example`: `PROJECT=your-project-id`, `OWNER_UID=`.
- `scripts/deploy.mjs` (plain Node): read `deploy.env`; abort unless `PROJECT` is a real project ID matching `projectId` in `web/firebase-config.js` and `OWNER_UID` matches `^[A-Za-z0-9]{28}$`; render template → `.build/firestore.rules`; `--dry-run` or `DRY_RUN=1` stops after printing; else `npx -y firebase-tools@15.34.2 --project <PROJECT> deploy --only hosting,firestore`; then fetch `https://<PROJECT>.web.app/`, expect 200.

### Task 3: Data layer (library, saves, settings, IndexedDB cache)

**Files:**
- Create: `web/idb.js`, `web/library.js`, `web/saves.js`, `web/settings.js`; Test: `web/library.test.mjs`, `web/saves.test.mjs`, `web/settings.test.mjs`

**Interfaces:**
- Consumes: Task 1 `parseHeader, splitChunks, joinChunks, sha1Hex`; Task 2 `db` + Firestore helpers.
- `web/idb.js`: `idbGet(store, key) -> Promise<any>`, `idbPut(store, key, value)`, `idbDel(store, key)`; DB `gbc-to-go`, stores `roms`, `saves`.
- `web/library.js`:
  - pure: `uploadPlan(meta, chunks) -> Array<{ path: string[], data: object }>` — chunk ops `['roms', id, 'chunks', String(n)]` first, meta op `['roms', id]` **last**.
  - `uploadRom(file: File, onProgress?) -> Promise<RomMeta>` — parse, hash; if `roms/{id}` exists return it (no-op); else one `writeBatch` from `uploadPlan`; `idbPut('roms', id, bytes)`.
  - `listRoms() -> Promise<RomMeta[]>`: `getDocs(collection(db,"roms"))`, sorted client-side by `lastPlayedAt` desc (null last, then title). No Firestore `orderBy`: it drops docs missing the field.
  - `loadRomBytes(id) -> Promise<Uint8Array>` — IndexedDB first, else read `chunks` ordered by doc id numeric, join, cache.
  - `markPlayed(id)`; `deleteRom(id)` — deletes chunks, `saves/{id}`, `states/{id}`, meta, and IndexedDB entries.
  - `RomMeta = { id, title, cgb, size, chunks, uploadedAt, lastPlayedAt }`.
- `web/saves.js`:
  - pure: `pickNewer(a, b) -> a|b|null` by `updatedAt` millis (either may be null).
  - `loadSram(id, { cloud }) -> Promise<Uint8Array|null>` — cloud: `getDocFromServer` with fallback to IndexedDB on error, `pickNewer` of both; local only when `cloud` false.
  - `writeSram(id, bytes, { cloud })` — always IndexedDB `{ sram, updatedAt: Date.now() }`; Firestore `setDoc` when `cloud`.
  - `loadState(id) -> Promise<Uint8Array|null>`, `writeState(id, bytes)` (Firestore `states/{id}`), `hasState(id)`.
- `web/settings.js`: `DEFAULTS = { cloudSaves: true, saveStates: true, autoStateOnExit: false, touchPad: 'auto', sound: true }`; pure `mergeSettings(stored) -> settings` (unknown keys dropped, wrong types → default); `loadSettings()`, `saveSettings(s)` on `settings/main`.

- [ ] **Step 1: Failing tests** (pure functions only; Firebase modules must not be imported by the pure parts — keep pure helpers importable without side effects, e.g. put them at top of module and lazy-import `./firebase.js` inside async functions, or split into `*-logic.js`):
  - `uploadPlan` for 2 chunks → 3 ops, last op path `['roms', id]`, first `['roms', id,'chunks','0']`.
  - `pickNewer({updatedAt:1},{updatedAt:2})` → second; `(null, x)` → x; `(null,null)` → null.
  - `mergeSettings({sound:false, bogus:1, touchPad:5})` → DEFAULTS with `sound:false`, `touchPad:'auto'`, no `bogus`.
- [ ] **Step 2:** `npm test` → FAIL. **Step 3:** Implement. **Step 4:** `npm test` → PASS.
